# Security and operational limits

- Backup administration requires a Redmine administrator. Rails authenticates users and protects POST actions against CSRF. Provider OAuth uses one-use state, expiry, destination binding and S256 PKCE. No SMTP application permissions are reused for storage.
- Secrets are write-only in the UI and encrypted in mode-0600 control files within mode-0700 local storage. No raw subprocess/provider errors or credentials are logged. Do not serve that directory through nginx/Apache/static aliases. Filesystem paths are administrator-only information.
- Archive encryption is disabled by policy. Dumps, environment files and the private bootstrap can contain credentials/customer data. HTTPS/SSH transport verification remains required. Limit storage access appropriately.
- The plugin performs no privilege escalation. External secrets/environment files must be readable by the Redmine account; unreadable required coverage fails capture. Redmine file/directory environment references are discovered on all platforms. Existing Linux unit files are optional metadata sources; they are never needed to start the backup worker. Additional paths are configurable.
- PostgreSQL capture inspection uses an explicit repeatable-read, read-only transaction. A database snapshot covers the dump and referenced attachment inventory, not an atomic whole-filesystem snapshot. Referenced attachments are hash/size checked while copied; changes to other copied files fail when detected. Long snapshots may delay vacuum cleanup and should be monitored operationally.
- Only one writer process is allowed per shared local control directory. Do not use an unreliable network filesystem for control locks or deploy multiple independent stores against one namespace. The worker has a kernel lock and heartbeat; it does not permit unsafe automatic takeover of a still-running hung process.
- Disk reserve checks use native Windows free-space APIs or POSIX `df -Pk`, with a one-second sampling cache during fast file streaming. Timeouts are checked on every call. Windows storage privacy is verified from actual DACLs, not chmod bits; private directory rules allow only the Redmine account, SYSTEM and local administrators. Provision sufficient disk capacity and perform a restore/space drill.
- Retention checks installation/run ownership and reference namespaces. It never synchronizes a whole bucket or folder. Completion markers are removed before deleting eligible payloads so partial deletion cannot remain advertised as complete. Interrupted deletes may leave orphaned objects; these are not blindly swept. Duplicate completion markers are preserved rather than risking shared-payload deletion.
- S3 Object Lock can be irreversible until expiry. The plugin checks existing capability and requests opt-in protection; it does not enable bucket policies, grant permissions or bypass holds. Versioning does not imply immutable protection. Old versions/provider recycle bins can outlive the configured successful-date count.
- Provider credentials/grants can be revoked and rates/quotas vary. No provider integration is claimed as production-certified by unit mocks. Personal OneDrive uses delegated identity; business/SharePoint application access requires explicit drive/site addressing. Shared Drive and SharePoint policies require separate testing. New application private keys and device codes remain encrypted; managed-identity metadata requests are restricted to local/link-local endpoints and bypass proxies.
- Alerts use existing Redmine delivery. Redmine supervises/restarts its worker and owns its lifecycle; no external worker supervisor is required. A dead application/server cannot run native alerts or backups. Startup catch-up resumes after availability; independent infrastructure monitoring remains an organizational choice.
- Recovery Mode is triggered by a different host identity, an explicit control/RECOVERY marker or `REDMINE_BACKUP_RECOVERY=1`. Identical VM clones may share identity, so restoration instructions require an explicit recovery flag. The plugin does not automatically restore a database or expose public backup download endpoints.
